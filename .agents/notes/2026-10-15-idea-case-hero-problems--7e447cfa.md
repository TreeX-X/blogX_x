# 想法：像素机箱 Hero 问题清单与成因分析（2026-10-15 用户反馈）

> 反馈记录与成因分析（2026-10-15），对应需求[像素数码 3D 机箱 Hero](2026-10-15-pixel-case-hero-requirement--f47e324c.md)。定案前的探索，不是承诺；修复方向待立项。

## 用户反馈（归纳）

1. **精度不够高、美术设计不好**——机箱辨识度与工艺感不达标。
2. **配色要符合 blog 画风和配色**——机箱应是站点视觉语言（暖纸 + 牛血）的正统表达。
3. **不要自转**——固定一个 **45° 角度**一屏看全所有部件；**可交互部件旁常驻标注线**（编号 + 名称引线）。
4. **像素→机箱变化不丝滑、非常生硬**——「树码空间」标题像素的打散重组观感断裂。
5. **周围控件布局让位不好、不自然**——进机箱态/选部件时页面控件与卡片的腾挪生硬。

## 问题与成因分析

### P1 精度不足

- 体素网格仅 52×78×38（`voxel-case.ts` W/H/D）：整机横向 52 格，显示宽度 ~760px 时单体素 ≈ 15 CSS px，块感过重。
- 细节被压成 1–2 格线段：风扇叶（r=4，7 叶折线点）、冷排鳍片（2 格步长点阵）、水冷管（5 段折线）、I/O（2×1 格）——在该分辨率下读作噪点而非「可辨识部件」。AC-2 的细节清单「装配层齐备」但**分辨率不足以传达**。
- LCD 用 256×160 贴图平面而非体素，与体素语言接缝明显。
- `lite` 降档（移动端）进一步抽稀装饰，精度问题被放大。

### P2 美术与配色偏离 blog 语言

- 色板虽取自 token，但主面全是 greige 近邻色（`glaze 0xe9eae6 / glazeLight 0xf8f9f6 / glazeWarm 0xebeae4 / glazeDeep 0xd9dad5`），彼此相差仅几个色阶；对页面底色 `--bg #f3f4f1` **图底不分**，机箱读作灰白团块。
- blog 签名色牛血 `#b93b28` 在箱体上只作毂/灯带/铭带等小点缀，**品牌色存在感不足**；反之 `ink 0x383a35 / shadow 0x151613` 大面积铺在显卡/冷排/主板上，读作「通用科技灰」而非暖纸工艺。
- 光照弱塑形：Hemisphere 0.62 + 两盏方向光，`MeshLambertMaterial` + 无阴影无描边，体素棱线只有 0.06 缝隙——对比度低、缺乏工艺感（对照 2026-10-14 纸板方向的丝印/胶带/瓦楞等工艺语汇全部丢失）。
- LCD 深色屏是箱上唯一大暗块，与浅色站整体观感冲突。

### P3 视角与标注模型（方向变更）

- 现行为与用户想要的直接冲突：
  - 空闲自转（`pixel-case-scene.ts` tick 中 `cam.az += dt * 0.0022`，即需求 EB-6 / 空闲态慢速 orbit）；
  - 点击部件相机飞到 `PART_POSES[p]` 各异机位（EB-5 / AC-4「自动旋转到最佳展示位」）。
- 用户改为：**固定 45° 一屏全景**（前脸 + 玻璃侧 + 顶面同框，五部件同时可见）+ **常驻引线标注**（编号 + 名称，部件旁标注线）。
- 3D 实现把 2026-10-14 纸板版的 `CALLOUTS` 引线模型整个丢掉了——现在只能点击出卡片，没有常驻标注；用户召回的正是该交互模型。
- 影响面：EB-5、EB-6 作废；`PART_POSES` 逐件机位闲置；腾位逻辑可大幅简化（相机不动，只平移/让卡片）。

### P4 像素→机箱变形生硬

- **交棒空窗**：`enterCase` 先 `setMode("toCase")`（标题 0.32s 淡出），再 `await ensureScene()` 动态 import three + 建场——首点冷加载 100–500ms+ 期间舞台是空的，标题消失 → 空白 → 粒子突现，断裂感的主要来源。
- **像素对应关系是假的**：标题采样点数（数百，step≈6–10 CSS px 稀疏采样）远少于体素数（数千），每体素取 `i % nSrc` + ±1.5 抖动——大量体素共用同一起点，是「粒子云重聚」不是「像素变形」；且采样破坏了标题像素的网格对齐（PixelWaveTitle 本身是干净的 cell 网格）。
- **长途爆散**：二次贝塞尔控制点外抛 26–60 世界单位（`seedMorph` burst），每个粒子飞长弧——正是 2026-10-14 已记录的「长途飞行糊成色块」教训换皮重演；1.75s 全程 easeInOutCubic，无分段缓动差异，整体读作「爆开再收拢」。
- 2D 标题方块（CSS 像素、平面）与 3D 体素（0.74 缩放立方、受光照）形态不一致，交棒瞬间形状/明度跳变。

### P5 布局让位不自然

- **图谱下移是跳变不是过渡**：`grid-template-columns` 从 `minmax(0,1fr) 380px` 切到 `minmax(0,1fr)`，轨道数不同 CSS 无法插值，`.45s transition` 无效——sidebar 位置瞬间弹跳；`kg-panel` 高度 560→320 同理。
- **多套计时器互不同步**：min-height 0.55s / 标题淡出 0.32s / 变形 1.75s / 图谱 0.45s 各走各的，页面在变形还在飞的时候就开始重排，观感是「页面被拽走」。
- **hero 下方控件被顶推**：`pcx-root` min-height 展开把副标题/搜索框/特性卡直接下推，无编排。
- **卡片腾位跳两次**：`setCardShift` 世界平移 ±16 与相机 az 同时动（复合运动）；卡片 `top` 用 0/480/900ms 三次 `setTimeout` 校正，相机阻尼落位后卡片会二次跳动。

## 与既有定案的冲突

- **EB-5 / EB-6 / AC-4（自动旋转最佳展示位、空闲自转）被用户否决**——固定 45° + 常驻标注线取代。
- 决策[像素机箱方向](2026-10-15-decision-pixel-case-hero-direction--32ddac56.md)「暖纸像素陶瓷」执行结果被否：token 纪律没违反，但**色值配比、图底关系、工艺感**不达标；体素审美是否重开决策待定（倾向重定「牛血为主导、暖纸为底、工艺语汇回归」）。
- 2026-10-14 纸板版的引线标注交互模型（常驻 CALLOUTS + 就近卡片）被用户召回，叠加到 3D 体素载体上；纸板画风本身仍作废。

## 修复方向（待立项，仅列不展开）

1. 精度：体素密度提档（或壳体/部件双分辨率）+ 细节清单按新分辨率重画；LCD 与体素语言对齐。
2. 配色：牛血升主导、暖纸降灰、去大面积 ink/shadow 灰块；对照 blog 图底关系重调光照与描边。
3. 视角：固定 45° 全景机位（约 az=-135°/el≈25°），常驻引线标注层（SVG overlay 投影挂体素坐标，或 CSS2D），相机不动。
4. 变形：先预载场景再放标题（消灭空窗）；标题像素 1:1/网格对齐采样直飞目标位（放弃爆散长弧）；分段缓动 + 拖尾。
5. 让位：图谱下移改 FLIP/transform 编排（绕开 grid 轨道插值限制）；卡片 top 一次定位（投影稳定后），与场景腾位共用一条时间线。
